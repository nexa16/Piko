# Piko application

Local-first Flutter application under Android testing. The current [round-6 build-7 checkpoint](../docs/implementation-round-6.md#checkpoint-handoff--2026-10-17) includes the approved vocabulary-list controls, EN/DE learning help, transient vocabulary selection and affected Collection interaction anchoring. Scoped host/Android evidence and remaining limitations belong to the ledger; earlier round-5 behavior is retained. Statistics, the shrinking header and documentation migration are authorized but deferred. F22 was withdrawn because the owner could no longer reproduce it; no verified fix is claimed. This is a local development candidate, not a release.

Toolchain baseline: Flutter 3.44.7 stable, Dart 3.12.2. Android application ID: `io.github.nexa16.piko`.

The real Settings route applies and retains English/Deutsch interface language through the runtime's existing SQLite `locale` setting. `PikoApp` owns only its internal locale controller; an injected controller remains caller-owned. With `PikoRuntime`, retained valid language overrides the injected initial composition and missing/unsupported preferences use English. A custom non-runtime `home` continues to use the injected locale/controller without storage hydration. Language changes preserve navigation and current feature state. Host acceptance does not replace the pending detailed Settings UX or Android verification.

From this directory, run `flutter pub get`, `flutter analyze`, `flutter test`, then `flutter run` with an Android emulator or development device available.

Android acceptance must use a fail-closed installation path: build the test APK, install with direct `adb install -r -t`, stop on any install error, start it manually, and attach using `flutter drive --use-existing-app=<forwarded VM service URL> --driver=test_driver/attach_only.dart`. Flutter 3.44.7 can uninstall after an installation failure even with `--no-uninstall`; that flag prevents only normal test teardown uninstall. Do not use automatic Flutter installation on a preserved device. Historical `flutter test --no-uninstall` commands below identify test targets, not the current safe installation procedure. Use isolated fixture storage and a verified backup, check the pre-existing sentinel after testing, and restore the normal same-schema APK with a direct in-place install. Never infer data preservation merely from seeing a newly created database after relaunch. Do not use these integration commands on a personal device without explicit approval.
