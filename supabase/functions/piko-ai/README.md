# Private AI test service

Local implementation; deployment and activation are separate. App/server build gates and SQL admission default off. Public project configuration never grants access; provider/service-role secrets stay exclusively in the server secret store. Missing configuration fails closed.

Run `npm ci --ignore-scripts` and `npm test` here. Pinned PGlite tests exercise both the preserved first migration and the r2 pilot migration; fetch fixtures never make paid calls. Queued simultaneous PGlite requests exercise atomic statements, but do not establish hosted multi-connection behavior. `index.ts` pins its SDK and verifies anonymous Auth using `getUser(jwt)` plus a matching live `auth.sessions` row from the verified token. Missing, revoked or expired sessions fail closed; user metadata grants no permission. The session-check migration grants the server role only the three required Auth columns, with no app-role RPC access.

## Admission and activation

Use a dedicated, separately approved project. Apply the admission, private-pilot, session-check and cleanup migrations in order. The declared Auth configuration enables optional anonymous sessions, short access-token lifetimes and bounded enrollment; it does not invite an identity or enable paid dispatch. The second disables the prior owner-only configuration. Provision fixed nonreusable invitation slots 0–5 (0 for the owner), one Auth UUID per slot, with individual expiry/revocation; never grant slots through a client API or recycle them during the pilot. Verify identity recovery manually before any later pilot instead of silently rotating allowance.

The config stores one start/end interval of exactly 14 days, reviewed maximum all-in input/output prices and conversion, conservative per-request reserve, shared usage allowance, non-AI usage, available prepaid balance and new cash outlay separately. The configured caps are checked without double-counting purchase and usage. No monthly reset, renewal, top-up or paid fallback exists. Do not reset the reserved/spent counter. Admitted failed/uncertain attempts count. Unknown outcomes retain both cost reservation and an in-flight slot even after polling expiry; reconcile them explicitly before admitting further work. Secondary limits are 20/identity/UTC-day, two/minute, one in flight; all identities share the global balance. Provider processing is fixed Sol low with strict schema, no tools/second judge, background processing and `store:false`. One POST is one attempt; owned GETs only poll it.

Before setting `deployment_verified`, verify actual prices/tax/FX/fees, Free-plan eligibility, funding and allowance, region/processors, Auth/JWT/session/abuse controls, secure transport/storage, private schema grants, required maintenance and ALL managed-copy/backup expiry. Supply the real notice version, invitation contact and processor/storage details. Activation needs separate authorization and source-bound verification; setting a flag is not evidence that these checks passed. A stale/missing cleanup heartbeat denies new calls. Do not edit the fixed interval to renew it.

## Consent and private analysis

Authenticated POST control operations use `?pilot=notice|consent|withdraw|feedback|adoption`; ordinary clients have no table/RPC grants. Consent requires the current notice version and an invited identity. Withdrawal remains available when AI dispatch is disabled, immediately revokes that identity and deletes its live payloads. Keep the endpoint/Auth path available after pilot expiry so withdrawal can finish. Admin revocation also blocks dispatch/status/logging; daily cleanup removes its content. No cross-tester payload read endpoint exists.

Accounting receipts contain only operational metadata. The separate private payload store captures the actual request/provider body, actual output (including invalid paid outcomes), refinement lineage, version information and reported adoption/optional feedback. Nothing is printed to application logs. Client adoption is reported after the local atomic commit; delivery failure means unknown adoption, never an excuse to repeat the local write. Retained context excludes learning/statistics and unrelated Collections. Regression records require explicit human de-identification review; app/server roles cannot create or read them.

## Expiry and copies

The cleanup migration installs database-owner maintenance every six hours: `select public.piko_ai_cleanup();` then `select piko_ai_private.purge_inactive_anonymous_identities();`, and runs it once initially. Verify the actual scheduler, database owner and heartbeat on the selected deployment. The cleanup service role is intentionally revoked because regression cleanup requires owner access. Raw live payloads expire after 22 days, leaving at most one day of scheduler delay and seven days for every backup/copy (30-day upper bound). Withdrawal deletes live payloads immediately; every managed copy must expire within seven days. A copy/export must retain the original expiry, never restart its clock. Restores must apply revocations/deletion requests and cleanup before service activation. Do not enable managed backups/PITR or external exports that violate these bounds. Verify deletion across an actual backup/restore before activation; SQL alone does not prove it. Cleanup heartbeat is a fail-closed admission guard, not a substitute for a running job and operational monitoring after service shutdown.

Reviewed de-identified regressions expire after at most 82 live days and no later than pilot-end plus 82 days, preserving the same one-day maintenance/seven-day copy margin inside 90 days. Keep identities/raw quotes out of these rows. Receipt metadata expires after 35 days; inactive anonymous Auth identities/sessions after 90 days without recent activity. Unknown cost reservations are not refunded by deletion. This dedicated-project cleanup must not run against unrelated users/projects.

Provider retention is separate: background responses may remain approximately ten minutes even with `store:false`, and standard processing applies. See [OpenAI background processing](https://developers.openai.com/api/docs/guides/background). No zero-retention promise or provider-wide log deletion is made.

Before live use run hosted advisors, role/isolation tests, two real concurrent connections at the shared cap, expiry/replay/withdrawal races, session refresh, deletion across copies and revision-specific Android managed-provider flows. Local fixtures are not live language-quality or hosted-retention acceptance. No deployment, purchase, invitation, distribution or publication is performed by these files.
