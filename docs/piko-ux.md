# Piko — UX Specification

**Version:** 0.5.0 · **Updated:** 2026-10-16

This file defines screens, content hierarchy, controls, layouts, interaction affordances and localization. Functional behavior is defined in [`piko-functional.md`](piko-functional.md); references in parentheses identify the related functional requirements.

`Round`, `Updated` and `Fix` tags refer to implementation rounds, not published versions. Stable IDs and revisions remain the traceability unit inside thematic feature PRs; each accepted feature PR is squash-merged into `develop`. Publication and a release branch require a later owner decision.

Inline `[Flow: collection]`, `[Flow: entry]`, `[Flow: review]`, and `[Flow: settings]` tags associate UX requirements with Collection creation/opening, manual entry, self-assessment review, and basic settings. A comma-separated tag denotes several associations. Flow is a topic filter, not a scope or acceptance label: optional features such as typed answers, import, AI, and statistics stay optional under the functional Scope classification. Mixed UX requirements remain intact; showing their basic portion does not claim the whole requirement is implemented.

### Persistent selection actions and header alignment — accepted, 2026-10-16

**Owner report:** Several popups have excessive blank footer space before changes. In Filters, sometimes only Clear filters / Filter zurücksetzen is visible; selecting a value adds Apply and moves the existing clear action. The owner reports stacked actions on a phone and side-by-side actions on an emulator, and an X that is not aligned with the title. The supplied changed-state image shows one Unit group, U 1 unchecked and U 2 checked, both footer actions visible, and an X visually lower than the title. The exact opening selection, device/viewport/text scale, build and repeat frequency were not established; the other affected popup names remain unenumerated.

**Direct evidence:** A bounded check of the local round-3 Design Lab in English used Korean Basics, Topic values Food/School, and no confirmed category filters. Open Filters → select Food → inspect → dismiss with X without applying. Apply was initially absent and appeared after selection. The reserved action slot measured 64 CSS px and the popup measured 351 CSS px before and after the edit in that browser fixture. This confirms the empty reservation and changed-only visibility; the reported clear-action movement was not reproduced in that fixture. No Android/device reproduction or cross-popup runtime audit was performed. Source inspection shows shared selection-footer and header rules; that is not device verification.

**Accepted behavior:** The owner selected always-visible actions with disabled states. This supersedes revision 4’s hidden Apply/empty reserved footer for editable selection popups, including Filters and category assignments. Keep the existing horizontal/stacked reflow policy; always stacking was suggested but not selected. The X alignment is a fix against the existing shared-header rule. Separate inline category-name/value saves, direct-launch choices, confirmations and summaries retain their own action/dismissal contracts.

**Acceptance scenarios (pending in mockup and Android):**

- Open Filters with no confirmed selections: Apply and Clear filters are both visible and disabled. Selecting Food enables both without moving either action, the title or the selected row.
- Open with Food already confirmed: Apply is disabled and Clear filters is enabled in their final positions. Adding School enables Apply without moving Clear filters.
- Clear that nonempty opening selection: Clear filters disables, Apply enables, search is retained, and confirmed filters remain unchanged until Apply. X/Escape/backdrop/system Back cancels the pending clear.
- Starting with no confirmed selections, select then clear; or otherwise restore exactly the opening set: Apply disables again without disappearing. Clear filters is enabled exactly when the pending set is nonempty.
- A category assignment picker keeps its single Apply action visible and stationary through unchanged, changed and reverted states, without adding a clear action that does not belong to that picker.
- Exercise both horizontal and stacked layouts in English/German, including narrow width, 200% text and limited height. Compare action/title/row positions at each fixed layout; disabled state alone never changes arrangement or dimensions. Scroll long bodies and retain reachable actions, safe focus and non-overlapping touch targets.
- Check shared X alignment in Filters, category assignment and another existing form/summary with an X, using one-line and wrapping titles. The glyph aligns to the first title line, retains a 48px target and does not drift when title text grows. Confirmations that intentionally omit X stay unchanged.

## Unified popup design — accepted, 2026-10-15; selection actions updated 2026-10-16

The following popup family describes UX-DIALOG-001 revision 5, including the 2026-10-16 persistent selection-action decision; integration remains pending. Equal-width side-by-side actions and X on every popup were considered and not selected.

| Existing popup purpose | Accepted visible dismissal and actions |
| --- | --- |
| Destructive confirmation, such as Collection/category deletion | Cancel plus the specific destructive verb, with no redundant X. Keep the affected object and consequence explicit. |
| Unconfirmed-entry exit | Continue editing plus Discard & exit, with no redundant X. Escape, system Back and backdrop continue editing and preserve the draft. |
| Collection creation, Speed/setup forms requiring confirmation and category forms | Top-right X plus the meaningful Create/Start/Save action. Preserve each flow's existing validation, pending-write guards and draft rules. |
| Direct-launch picker, including the approved review direction picker | Top-right X and the existing body choices; no additional confirmation footer. UX-SETUP-001 retains its two stacked full-width direction/count buttons that start directly. The footer sizing rule does not resize these choices. |
| Review summary or informational content with no decision | Top-right X; no duplicate Close footer or new Back to Collection CTA. Routine status/error messages stay in their existing inline locations. |
| Editable category assignments and filters | Top-right X cancels pending selections. Apply/checkmark stays visible below the content, disabled when unchanged or reverted. Filters also keeps Clear filters visible, disabled when its pending selection is empty. Enabled-state changes never reposition either action. |

**Round-2 popup audit scope:** Collection actions with expandable category management; new Collection; Collection rename fallback; Collection deletion; review direction picker; category assignment; Filters; Add dimension; category/value deletion; Speed setup; unfinished-entry exit; and the reused review summary. JSON interchange remains a page with an explicit aggregate confirmation, not another popup. Creation and Start actions represent an explicit operation and remain available with valid defaults; selection Apply remains visible but is enabled only for changes; separate inline edit/save rules remain unchanged. Creating a category value is an independent explicit save and does not implicitly Apply the surrounding assignment draft. Closing that picker discards only pending assignments, not a value explicitly saved within it.

**Shared geometry:** Keep the existing flat surface, shared radius, maximum width and padding. Give title and body one leading edge. Place X, when present, in a fixed trailing header slot aligned to the first title line; reserve its target space so long titles wrap without pushing it down or overlapping it. Use one body-to-footer gap. Group content-width footer actions at the trailing edge (right in English/German), secondary/safe action first and affirmative/destructive action last. Use consistent height and spacing, not equal prominence for every action. If labels cannot fit at the current width/text scale, stack full-width actions with the affirmative action above the safe dismissal; visual, keyboard and semantic orders must agree. Never truncate a decision label. An X at top-left is associated with some full-screen modal app-bar patterns; do not alternate its side within Piko's current contained popups or introduce full-screen flows through this decision.

**Acceptance checks (prototype separately from Android):** Check Collection creation/deletion, draft exit, review setup/summary and round-2 category/Speed dialogs at 320px and normal mobile widths in English/German, at normal and 200% text and with keyboard present where relevant. Keep all text/actions available by scrolling when necessary; preserve safe insets, non-overlapping 48dp Android touch targets, contained focus and opener focus restoration. Verify X is absent from confirmations and present in forms/setup and summaries; safe and affirmative controls follow the shared order in horizontal and stacked layouts. Confirm dismissal never performs the affirmative action or silently discards the entry draft; pending saves retain their existing guards. Do not initially focus a destructive action or make it the implicit Enter default; explicit keyboard activation of the focused action remains supported. Source labels and geometry from the canonical copy/design configuration. No new confirmation is added to reversible vocabulary deletion. Research and rationale: [DESIGN.md](DESIGN.md#popup-design-research-and-accepted-family--2026-10-15).

  Piko spreads your reviews over time to help you remember vocabulary for longer.
