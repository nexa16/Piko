# Piko — UX Specification

**Version:** 0.4.2 · **Updated:** 2026-10-13

This file defines screens, content hierarchy, controls, layouts, interaction affordances and localization. Functional behavior is defined in [`piko-functional.md`](piko-functional.md); references in parentheses identify the related functional requirements.

Inline `[Flow: collection]`, `[Flow: entry]`, `[Flow: review]`, and `[Flow: settings]` tags associate UX requirements with Collection creation/opening, manual entry, self-assessment review, and basic settings. A comma-separated tag denotes several associations. Flow is a topic filter, not a scope or acceptance label: optional features such as typed answers, import, AI, and statistics stay optional under the functional Scope classification. Mixed UX requirements remain intact; showing their basic portion does not claim the whole requirement is implemented.

## Learning Card — confirmed UX

- **UX-DIALOG-001 [Confirmed]:** [Release: First] [Flow: collection, entry, review, settings] All popups share a title row with a localized close X at top-right and consistent safe Escape/backdrop dismissal with focus restoration. Closing never creates, deletes, starts review, saves or discards a draft. Draft-exit dialogs retain meaningful Continue Editing and Discard & Exit choices; X/Escape/backdrop means continue editing without data loss. Inline edit cancellation is separate from popup dismissal.

- **UX-REVIEW-004 [Confirmed]:** [Release: First] [Flow: review] Present the session summary as a modal popup, not a separate page: two prominent readable numbers for vocabulary learned and first-try correct, with labels allowed to wrap naturally. Include a short friendly motivational message below the title and above the metrics, without exaggerated performance claims; its wording is editable through shared English/German copy. Use a normal localized close X, Escape and backdrop dismissal; return focus to the underlying Collection. Do not add a Back to Collection CTA. The production popup uses canonical 36px tabular numbers and stacks metrics when enlarged text cannot fit side by side. Each metric exposes its number and localized label together to accessibility services. Eight English/German 320px/200% tests cover readable immutable counters, all four dismissal paths including system Back, focus restoration and absence of prototype text/extra CTA. Two passing English/German Android real-runtime flows additionally reach the popup with exact accessible 2 completed / 1 first-try metrics and dismiss to the underlying Collection. Broader release gates remain separate.

## Entry Editor, categories and import review — confirmed UX

- **UX-ENTRY-001 [Confirmed]:** [Release: First] [Flow: entry] Manual entry uses a smooth scroll-driven Focused Card Stack; the centered card expands automatically and nearby cards collapse to previews. New Entries require Confirm & Next; already saved Entries auto-save edits. (ENTRY-001–008; deletion details and precise thresholds remain separately tracked in ENTRY-009–010)

Active cards use the primary border; inactive cards show strong target and muted native previews. Save & Next is a localized primary checkmark with a 48px minimum target. State transitions use 200ms, with reduced motion suppressing transitions. Dynamic measured centering avoids freezing experimental prototype viewport heights or edge padding. Android verification uses the real production screen with isolated SQLite data, 200% German text, actual IME resizing and swipe activation without opening the keyboard. Header Back/global completion arrangement remains UX-ENTRY-002; routing, exit and deletion retain their own requirements.
- **UX-ENTRY-002 [Confirmed]:** [Release: First] [Flow: entry] Keep Back top-left and a global completion checkmark top-right outside the cards, with distinct localized accessible names and tooltips. Global completion confirms the last valid draft and exits; incomplete input shows validation and remains open. Back warns before discarding a nonempty draft. The active new card has a separate Save & Next checkmark. (ENTRY-007, ENTRY-011)
  The production header matches the binding grid: intrinsic zero-padding Back, a title centered within the middle track, 10px track gaps and a primary 48px global checkmark. Canonical header title sizes are 22px and 18px at/below the viewport's canonical 400px threshold, with the binding -1px letter spacing; generated responsive CSS and Flutter consume that same configuration. Back uses body/compact-small text with weight 750 and at least the shared 44px touch height. Canonical page-top padding and title margins are reused. The header action's localized Save last entry & end session name/tooltip differs from the active card's Save & Next; decorative icons do not add duplicate announcements. Keyboard traversal reaches Back, global completion, the focusable stack, active fields and card confirmation. At 200% German text the middle title may break a long word over multiple lines, matching the binding's anywhere wrapping; actions remain reachable, not a claim of flawless large-text typography. Route behavior remains the established ENTRY-007/011 behavior; Collection route wiring and whole-release acceptance are not implied by this header audit.
- **UX-CAT-001:** [Flow: collection, entry, settings] Show up to two Category Dimensions expanded by default, in user-configurable order; selected Values remain visible in collapsed headers. Allow multiple expanded dimensions, two rows of chips before Show more/search picker; avoid nested scrolling. (CAT-006–009; CAT-007–008 remain proposed)
- **UX-CAT-002:** [Flow: collection, entry, settings] Mark AI-preselected Values with a small sparkle icon, including in collapsed Dimension headers; no separate AI Assisted heading is required. Manual edits are never overwritten by delayed AI suggestions. (AI-001–006)

## Localization

- **UX-ICON-002 [Confirmed]:** [Release: First] [Flow: collection, entry, review, settings] Use Lucide as the common UI icon family. Keep size and stroke consistent, use accessible names for icon-only controls, and preserve upstream license notices. Flutter's typed PikoIcon consumes the same pinned SVG originals under `mockups/assets/icons/lucide`, with canonical `components.icons.size`, original 2px view-box strokes and inherited control color (canonical ink fallback). Icons are decorative by default; an optional semantic label names meaningful standalone imagery, while PikoIconButton owns action names and activation. Bundle the full ISC and Feather MIT notice and register it once at application startup. Individual screens integrate these shared icons in their own specification commits.

- **UX-SETTINGS-001 [Confirmed]:** [Release: First] [Flow: settings] First-release Settings shows a single App Language control with English and Deutsch. No learning, Hint, developer, or theme preferences appear in that release view. Keep one page title and usable Back navigation.
  The real runtime route has one level-one semantic heading, one localized App Language dropdown and one Back action, without extra explanatory headings or excluded controls. English/German host tests at 320px and 392px with 200% app text scaling verify contained, reachable ≥44px Back/dropdown/menu targets, actual Tab/Space/arrow/Enter language selection and keyboard Back returning to the same Home state. A visible-text allowlist and control inventory reject additional preference content.
  Measured normal binding title-to-card spacing is 23px after CSS margin collapse. Flutter reuses the existing 7px heading margin plus 16px `spacing.4`; the browser uses the same sum rather than an independent Settings literal. The card retains shared 19px padding/1px border and the binding field's 17px top/bottom margins through `components.settings.fieldMarginY`, applied only to Settings in Flutter and its scoped browser field. Normal host box tests verify the 23px title/card gap and 37px card-edge/field insets. A passing Android real-runtime EN→DE→EN flow with injected 200% app text scaling verifies live canonical copy and Material locale changes, contained and reachable ≥44px Back/dropdown targets, exact return to Home and persistence across file reopen while unrelated storage remains unchanged. Platform font scaling, assistive-reader traversal and whole-release accessibility remain separate gates.

- **UX-I18N-002 [Confirmed]:** [Release: First] [Flow: collection, entry, review, settings] Maintain one shared editable catalog for UI naming and English/German translations, consumed by the mockup and the application. The prototype supports live draft editing and export. Flutter consumes generated canonical catalogs through a shared widget context that rebuilds consumers when the interface locale changes.

- **UX-I18N-001:** [Release: First] [Flow: collection, entry, review, settings] Every visible string, including status labels, tooltips, controls and feedback, is localizable. English is default, German is supported initially. Production controls consume the canonical shared catalog, including errors, dialog dismissal, review correction and summary semantics.
